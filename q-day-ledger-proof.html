Second run: the live TLS scanner, against a real endpoint

The demo exercises the source, certificate, and dependency scanners. To prove the fourth scanner — the live TLS prober — we pointed it at a live TLS endpoint we control (a local openssl s_server presenting a fresh self-signed RSA-2048 certificate). It found 2 assets, both scored CRITICAL, and reported the endpoint correctly:

TLS key establishment — ECDH, score 78: "negotiated TLSv1.3 / TLS_AES_256_GCM_SHA384 (256-bit bulk); versions accepted: TLSv1.2, TLSv1.3" — both correct.
Certificate — RSA 2048-bit, score 87: signature algorithm sha256WithRSAEncryption and the certificate's validity dates parsed correctly from the DER.

The misses — published, not buried

9 of the 37 assets came back "UNKNOWN — identify the algorithm, then re-score." The tool flags what it cannot identify instead of guessing. In this run that was: 2 opaque firmware images (it reports signed vs. unsigned but does not identify the algorithm inside an opaque binary), 3 private keys (inventoried by type and size only — key material is never read beyond the header, by design), 3 libraries whose cryptography cannot be determined from a manifest alone (crypto-js, pycrypto, and the sample SBOM's OpenSSL 1.1.1w entry), and 1 unidentified source pattern.

Our first public-internet TLS probe failed. Probing jdawgsindustries.com:443 from our test sandbox returned a non-TLS response (SSL "wrong version number") — the sandbox's network path, not the endpoint. The tool recorded the failure as an asset — "TLS endpoint unreachable," with the probe error as its evidence — instead of silently passing. The controlled local-endpoint run above is the TLS scanner's verified behavior.

Phase 3 of the sample plan (the 2031 signature wave) is empty. Correct for this target — no sample asset lands there — and shown as-is rather than padded.

Stated limits of the product itself: the source scanner covers Python, JavaScript/TypeScript, Java, Go, C/C++, and configuration files — other languages are not scanned. The TLS prober sees only endpoints reachable from where it runs. Source and dependency scans list assets in filesystem-walk order (a documented v1.1 cleanup item; scores and deadlines do not depend on listing order). Engineer-day figures are planning estimates. Mandate rules are data files in the package — when a mandate changes, the rules update by editing JSON, and the dates on this page are the ones the shipped v1.0.1 rules carry.
